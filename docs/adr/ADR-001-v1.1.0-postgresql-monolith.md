# ADR-001: Prioritize a Verified Node/TypeScript Modular Monolith and PostgreSQL 16 for SAMT v1.1.0

- **Status:** Accepted
- **Date:** 2026-11-23 (Asia/Baku)
- **Context:** SAMT v1.1.0 (Milestone 3 / Report 3)
- **Supersedes (for local v1.1.0 scope only):** Preliminary Milestone 3 roadmap items in `report_2.md` §5.3 and target distributed stack notes in `SAMT_v1.0.1.md`

---

## 1. Context and Problem Statement

Earlier project documents outlined ambitious long-term distributed infrastructure:
- `report_2.md` §5.3 proposed executing a TimescaleDB 2.14 + PostGIS 3.4 schema under a 40,000 samples/s load, developing a Go or Rust mTLS 1.3 ingress microservice for `contracts/telemetry.proto`, and adding Pact consumer-driven contract testing.
- `SAMT_v1.0.1.md` (§7–§14) further described Apache Kafka, Apache Flink, Redis caching, database sharding, and a Python OR-Tools MILP container for national-scale ADSEA operations.

Meanwhile, a baseline audit of `main` (`4667e5d`) revealed fundamental correctness, concurrency, security, and wiring gaps inside the existing prototype itself:
1. No real HTTP server or persistent database backed the React UI (`InMemoryIncidentRepository` and `ValidatedJsonFixtureIncidentRepository` lost state on page reload).
2. Domain correctness defects existed in `flowIntegration.ts` (unbounded extrapolation outside windows), `incidentStateMachine.ts` (trusting caller-supplied `isSuccessful`), `InMemoryIncidentRepository.ts` (accepting same-version updates), `validation.ts` (process-local deduplication and unverified historical flags), and `contracts/schema.sql` (cross-meter averaging before multiplying by `0.25`).
3. Reimplementing these domain rules in Go, Rust, or SQL before fixing and verifying a single shared persistence workflow would duplicate business logic, multiply operational complexity, and risk building a distributed shell around unverified semantics (see `resources/lectures_merged.pdf`, p. 75 on complexity trade-offs and p. 128 on introducing distributed storage only when scale/availability requirements justify its complexity).

## 2. Decision

For **SAMT v1.1.0**, we implement a **single Node.js 22 / TypeScript modular monolith HTTP service (`server/`) backed by standard PostgreSQL 16 (`postgres:16.4-alpine`)** wired directly to the existing React 19 frontend (`prototype/`):

1. **Single Authoritative Domain Core:** Both the HTTP server and React prototype import the exact same pure TypeScript domain modules (`prototype/src/domain/`) and shared application use cases (`prototype/src/application/`). No hydraulic, verification, allocation, or savings algorithms are duplicated in a second language or in SQL continuous aggregates.
2. **Standard PostgreSQL 16 First:** All core persistence requirements—versioned migrations, durable telemetry storage with composite `(dma_id, metric, observed_at DESC)` indexing, durable deduplication, optimistic concurrency (`version` CAS), `command_id` idempotency, transactional audit logs, and a transactional notification outbox—run cleanly and reproducibly on standard PostgreSQL 16 without requiring TimescaleDB or PostGIS extensions.
3. **Server-Side Verification & Security Boundaries:** Role-based access control (`viewer`, `dispatcher`, `device`), device-to-meter/DMA bindings, server-owned `received_at` timestamps, and authoritative evidence-based repair verification are enforced on the HTTP server.
4. **Executable Contract Checks Over Unneeded Infrastructure:** We validate `contracts/openapi.yaml` (OpenAPI 3.1.0) against live HTTP integration tests and compile `contracts/telemetry.proto` with a real `protoc` binary, deferring Pact, Kafka, Flink, Redis, TimescaleDB/PostGIS, and Go/Rust mTLS ingress to the separately labeled **Target Production Architecture**.

## 3. Consequences

### Positive
- **Zero algorithm drift:** Persisted API balance queries, domain unit tests, and demo mode execute identical TypeScript integration and verification code.
- **Provable ACID guarantees:** Incident updates, version increments, command idempotency records, audit logs, and outbox notifications commit or roll back atomically in a single PostgreSQL transaction (`resources/lectures_merged.pdf`, pp. 4–5).
- **Reproducible local verification:** Anyone with Node 22 and Docker Compose can run migrations, deterministic seeds, integration/concurrency/rollback tests, a bounded workload benchmark, and a `pg_dump`/restore drill in minutes.

### Negative / Deferred to Target Architecture
- **No live mTLS 1.3 or gRPC/Protobuf transport yet:** Local v1.1.0 uses authenticated HTTP/JSON with environment-configured bearer/device tokens; `contracts/telemetry.proto` remains contract-only and compiled for schema verification.
- **No 40,000 observations/s cluster benchmark:** Local single-node throughput is measured honestly as a bounded single-machine benchmark rather than claiming unverified national-scale throughput.
- **Spatial GIS & TimescaleDB compression deferred:** PostGIS spatial queries (`ST_DWithin`) and TimescaleDB chunk compression/retention policies remain documented in `contracts/schema.sql` as optional future extensions once spatial queries or multi-year high-frequency retention justify them.
